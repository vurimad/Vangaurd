# Editor client

E0F update: Premake generation and the Debug and Shipping native UI lifecycle proofs now pass. Two hosts present, a detached output resizes and closes, and each 120-frame run exits cleanly. Debug font/image/clipping screenshots were inspected. Interactive docking/redocking and mixed-DPI/minimized updates remain open. See [the proof runner](tests/README.md), including the SDL3 prerequisite for direct project builds. This supersedes the E0E source-only validation statement below.

`editor` is a top-level product client alongside `runtime` and `source`. Its existing subdirectories are editor feature modules; `src` owns `EditorApplication`, while `platform/<platform>` owns native launch points. The Windows slice is a windowed executable with a native `wWinMain` entry and enters the framework through the Windows adapter.

The editor selects Runtime, Editor, and Tool profiles. It compiles and executes the same managed Frame Pipeline as runtime, so editor-only participants can join the graph without creating a second loop. World Session is available for play/edit world transactions without transferring engine-service ownership into editor states. The Game World participant is a deliberate no-op while no editable or play world is active. `--validate-bootstrap` verifies the complete native entry and teardown path without requiring window or rendering services.

`--validate-workspace` additionally traverses project startup, the empty/configured world decision, transition into the running frame pipeline, and symmetric shutdown before exiting after the first running frame.

Editor composition opens and validates the requested `.vproject` through the shared `projects` module before registering engine services. A managed Project Workspace service then owns the validated document and its resolved Assets, DerivedData, Intermediate, Saved, Builds, Config, and Plugins roots for the full editor-service lifetime. The project controls the project and derived-data filesystem roots, and its display name is reflected in the primary window title as `<project> - Vanguard Editor`. No project-specific knowledge is compiled into the editor.

`framework` owns the editor-local UI lifecycle boundary. `EditorUiService` is an `EditorWorkspace` service on the existing main-thread frame owner; it owns panel types and instances, stable host-window associations, stable editor texture identities, and the UI-frame state machine. Panel code is authored once per UI frame. A later private backend partitions finalized render data by native host, so panels are not incorrectly executed once for every detached window. Texture replacement creates a new generation rather than changing the resource behind an existing handle, allowing retained frame data to reject stale identities. Toolkit-owned atlas requests are separate: their immutable pixel uploads are retained once per UI frame and will be recorded once before that frame's host draws.

The framework API contains no toolkit types and does not provide widget-by-widget wrappers. Its private ImGui platform adapter owns one context, runs after the existing Input participant, forwards the ordered Vanguard input stream, consumes the Window Manager event journal, and translates ImGui platform viewport requests into Vanguard-owned native windows. Focus, cursor, clipboard and IME requests pass through generic Window Manager commands rather than direct SDL access. Each primary or detached host is paired with the existing presentation service and viewport manager; ImGui never owns their GPU objects. E0E captures retained draw data, submits atlas updates once through a headless graph, and renders arbitrary panel draw lists and textures through cached host-composition graphs. The existing frame renderer executes and presents those graphs in the same frame's chain, independently of scene graph builders. Geometry uploads and sampled textures use allocator declarations; reusable buffers and fence-retired descriptors avoid per-widget GPU allocation. The service keeps no locks or copied workspace state; its mutation contract follows the editor's existing main-thread ownership and render-tail join. E0E-C is source-complete but has not been compiled or executed; E0F must prove docking, detached hosts, texture display, DPI/resize and teardown.

`startup.editorWorld` selects an ordinary `.vworld`. The startup state supplies its typed identity and an explicit no-game-input policy to World Session. An empty value is a valid empty workspace. Project asset providers publish committed derived artifacts through the existing ResourceStreamer loose-source API; the E1 project asset foundation still owns that publication integration. The editor does not infer physical DDC filenames or automatically open `Builds/Windows/Development`. Optional packaged sources are selected explicitly with `--package-root <directory>` and mounted by Resource Streaming before renderer/world consumers; a supplied but invalid package root fails startup. Session `Running` permits asynchronous cell/component/residency progress and does not claim first-pixel readiness. Session stop releases world/input state; process sources survive until their owning service shuts down.
